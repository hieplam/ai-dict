# V4 — closing the real e2e gaps (verification-loop campaign, card 4)

**Depends on:** V1 (e2e folder cleanup merged first — avoids conflicts in the same directory).

**Goal (measurable):** three critical journeys with zero/weak coverage get real specs, all
running in CI: (1) browser-restart persistence, (2) landing-page drift, (3) hostile-page
minimum. Proof: new specs green in CI, and the landing-drift spec demonstrably fails when
`docs/index.html`'s install-state script is mutated (shown in a lock-style test or documented
local run, not committed).

**Why:** audit 2026-08-02: no test ever relaunches the extension against a persisted profile
(MV3 service-worker cold-wake rehydration unexercised); the c11 landing specs test a hand-copied
duplicate of `docs/index.html`'s script (drift undetected while merging to master IS deploying
the page); every spec runs on a synthetic one-paragraph fixture. All three verified technically
feasible — these are choices, not platform limits.

## Ratified scope (owner-delegated Shaman ruling, 2026-08-03)

### 1. Restart persistence spec

New spec: launch the harness with a REAL user-data directory (temp dir, not the empty-string
ephemeral profile), seed settings + at least one saved word, perform a lookup, **close the
context entirely, relaunch against the same profile dir**, then assert: settings survive, saved
word survives, and a fresh lookup works after the service worker's cold start. Extend
`fixtures.ts` minimally (an opt-in persistent-profile variant) rather than forking the harness.

### 2. Landing-page drift

Replace the hand-copied `INSTALL_STATE_SCRIPT`/`FIXTURE_HTML` duplication in the c11 (and c3
where applicable) specs: the spec reads the REAL `docs/index.html` at runtime (`readFileSync`),
extracts the install-state `<script>` block (fail loudly with a clear message if extraction
finds nothing — that failure IS the drift alarm), and injects it into the fixture. E2e must
still never fetch the live site (repo rule) — reading the file from disk is the sanctioned path.

### 3. Hostile-page minimum

Two new fixtures + specs proving select → Define → card works on:

- a page served with a restrictive Content-Security-Policy header (via the harness's route
  interception);
- a page whose own JS also listens on `mouseup`/`selectionchange` (and calls
  `stopPropagation`/`preventDefault` patterns a real site might).
  Deferred by ratified decision: iframes, shadow-DOM hosts, large real-world DOM — revisit only
  when a real bug points there.

## Out of scope

Safari automation (genuine platform limit — manual checklist stands), OS-level keyboard
shortcut synthesis (genuine Chromium limit), any scanner/doc work (V2/V3/V5).

## Acceptance

1. All new specs green locally 3 consecutive full-suite runs (repo zero-flake wall) and in CI.
2. Landing-drift spec fails when the real script block is mutated (demonstrated, not committed).
3. `docs/testing/e2e-case-inventory.md` updated per its own frozen bookkeeping rules (assertion
   counts / case rows) to include the new cases.
4. PR body: "Testing performed" section.
